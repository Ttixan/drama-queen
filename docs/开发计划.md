## 一、决策记录

这一节是**已拍板的设计决定**，不要再翻案。每条都标注了它推翻的原文。

### 1.1 骨架

| 项 | 决定 | 原 GDD |
|---|---|---|
| 游戏总长 | **21 天 = 3 周 × 7 天** | 表述含糊 |
| 行动点 | **1 点 / 天，共 21 点**；投递、打工、表演课、特殊事件各占 1 点 | 无此概念 |
| 投递上限 | **4 次 / 周**（3 周共最多 12 次） | 2 次 / 周 |
| 存档 | **每周结算自动存档** | "绝对不做存档" |
| 渲染器 | **Mobile** | Forward Plus |
| 语言 | **GDScript** | 配了 dotnet |

> 行动点是全局最硬的资源：**钱能欠，行动点只有 21 个。**

### 1.2 属性

状态栏四项：**金钱 / 演技值 / 知名度 / 风评**。另有一个**隐藏属性：负面曝光累计**（不上状态栏）。

- 「好感」系统整体砍掉（经纪人好感、朋友好感都不做）
- 「名声」统一改称**知名度**（两份 docx 已写死这个名字）
- 知名度 = 有多少观众认识你 → 决定电子报何时直接点名玩家
- 风评 = 观众对玩家的正面 / 负面评价

### 1.3 收益归属

**演技收益由角色难度决定，钱由公司档次决定。** 互不交叉。

| 角色档位 | 演技要求 | 匹配线 | 演技收益 |
|---|---|---|---|
| 龙套 | 0 | 30% | +1 |
| 配角 | 5 | 50% | +2 |
| 主角 | 15 | 70% | +5 |

### 1.4 四大 App 分工

| App | 职责 |
|---|---|
| **微信** | 消息中枢 + **投递入口**（私聊 HR）+ 随机事件 |
| **Boss直聘** | **只读**：公司信息浏览 + HR 信息展示 + **偏好线索（线索的唯一来源）**。玩家不在此投递 |
| **录像机** | 拼装 3 帧表情包 |
| **微博** | 每周一期电子报《有瓜有戏》 |

### 1.5 核心循环（最终版）

```
Boss直聘 ──浏览公司信息 / HR信息 / 偏好线索──┐
                                            │ 解锁 HR
录像机 ──拼 3 帧表情包──→ 表情包 ────────────┤
                                            ↓
微信 ──私聊 HR──→ 发送表情包 ══投递══→ 立即出：通过 / 失败
                                            │
                             ┌──────────────┘
                             ↓  本周末结算
                   ┌──────────────────────────┐
                   │ 《有瓜有戏》播出反馈       │
                   │ 高分 / 普通 / 低分         │
                   │ → 知名度 / 风评 / 负面曝光  │
                   │ 金钱 + 演技值              │
                   │ 房租 · PS5 分期 · 周总结   │
                   └──────────────────────────┘
                             ↓
                       结局判定 → 下周 / 结局
```

**关键时序规则**：
- 投递瞬间只出「通过 / 失败」，**不发钱不发演技**
- 钱、演技值、知名度、风评、负面曝光**全部在本周末结算**，与播出反馈一起
- 本周所有投递的作品，**统一在本周末播出**，汇总成一期电子报

### 1.6 表情包规则

- **一次性消耗**——每投一次就消耗掉，下次必须重新拼 → 保住"每次都要表演"的核心
- 录像机**不设可复用库存**；表情包列表只作**作品集 / 履历**展示
- 履历展示同时承担一个隐藏职责：为电子报的「标题调用条件」提供玩家过往经历标记

### 1.7 判定机制

**不用加权公式，用布尔条件 + 权重。**

```
匹配度 = Σ(命中的条件权重) / Σ(全部条件权重)
```

每个公司的条件是**布尔判断**（有没有"喜" / 有没有冲突情绪 / 帧间是否反转），
全部由数据驱动，好写、好测、好平衡。算出的百分比直接对接 30% / 50% / 70% 三条匹配线。

**难度层次来自条件在"质"上的差异，不是同一个数字变大。** 五档质变：

| 层级 | 公司 | 条件类型 | 玩家学到的表演概念 |
|---|---|---|---|
| L0 | A 烂片厂 | 最低条件（无冲突情绪） | 学会 UI：怎么拼满 3 帧 |
| L1 | B 小公司 | 单情绪命中 | 情绪是能被识别的 |
| L2 | C 商业片 | 情绪**纯度**（排除冲突情绪） | **克制** |
| L3 | D 文艺片 | 情绪**曲线形态**（递减 / 递增 / 平稳） | **表演弧线** |
| L4 | E 大厂 | **帧间反转** | **转折** |

> A 公司虽是最低档，但**必须给一条最低条件**，让它承担教学关职责。
> 否则玩家在 A 学不到任何东西，会带着错误认知去 B 然后连拒。

**配套硬需求**：条件越复杂，提示必须越多。「隐藏公式 + 只给情绪标签」的设定下，
**线索是必需内容，不是可选叙事** —— 每家公司一条 `CompanyData.hint`，
写在它自己的 **Boss直聘 招聘页**上；玩家进过那家公司的页面才看得到。

> 🛑 **Day 2 修订**：原设计是「经纪人邮件每周漏一条」。**经纪人角色已砍**（见 1.10），
> 线索改挂在招聘页上，玩家自己去打听。
>
> **顺便说清一件事：线索是方向，不是答案。**「重点在**纯**」≠「纯度 ≥ 0.55」——
> 玩家还得把它翻译成一段表演（哪几个部件、怎么排 3 帧）。所以一次性看全五家的线索**不算泄题**，
> 真正的难点始终是「知道方向之后，用手里 32 件部件拼出来」。

### 1.8 播出反馈

- 电子报名称：**《有瓜有戏》**，游戏中只显示标题
- 三档：**高分 / 普通 / 低分**
- 判定是二维的：**作品质量（公司档次）决定标题背景，玩家匹配度决定是夸还是骂**
  → 同一个匹配度既决定"能不能过"，也决定"播出后是高分还是低分"
- 标题称呼分级：龙套不点名 → 主要角色用角色定位 → 知名度够门槛才直呼玩家名
- **「黑红也是红」不做成成就系统**（GDD 边界写了"绝对不做成就"），改为一条微博标题

### 1.9 结局（按 12 次投递上限重写 · Day 1 二次修订）

| 优先级 | 结局 | 条件 |
|---|---|---|
| 1 | 影后 | 演技 ≥ 25 且 演过 E 公司主角 且 凑齐 PS5 费 |
| 2 | 文艺片女神 | 演技 ≥ 18 且 演过 D 公司主角 |
| 3 | 龙套之王 | **龙套档**成功演出 ≥ 8 且 演技 ≤ 12 |
| 4 | 烂片女王 | 演过的**烂片** ≥ 6 且 演技 ≤ 12（片子好坏由**公司自带的概率**在投递时摇出，见 `CompanyData.good_play_chance`） |
| 5 | 被解雇 | 累计失败投递 ≥ 8 且 欠债未清（金钱 < 0） |
| 6 | 平庸 | 凑齐 PS5 费但未达上述任何一条 |

> **⚠️ 约束一（数学）**：演技值单调递增，「成功演出 ≥ N」必然推出「演技 ≥ N」。
> 所以任何写成「成功 ≥ N 且 演技 ≤ M」的结局都必须有 **M > N**。
> 原文的「演出次数 ≥ 15 / ≥ 20」在 12 次上限下数学上不可达。
>
> **⚠️ 约束二（语义）**：龙套之王与烂片女王必须测**不同的东西**。
> 初稿把两者都写成「演得多 + 演技低」，只是数字不同 —— 玩家分不出区别，等于白做两个结局。
> 现在 **龙套之王 = 数量**（成功演了多少个小角色），**烂片女王 = 品质**（成功演了多少部烂片）。

### 1.10 砍掉「经纪人」角色（Day 2 拍板）

原设计里有一个**经纪人**（GDD：「微信：联系HR，**联系经纪人**，联系其他人」），
职责是每周漏一条公司线索给玩家。**Day 2 拍板：整个砍掉。**

| 理由 | 说明 |
|---|---|
| **职能重复** | 「了解一家公司」这件事 Boss直聘 已经完整承担了（公司信息 + HR + 招聘页原文）。再养一个只负责转发线索的信息中介，是两套系统干同一件事 |
| **线索有了更好的家** | 招聘页本来就是**公司自己在说话**的地方。把「这家想要什么」写在它的招聘页上，比让第三方转述更自然，而且顺带奖励了「真的去看页面」这个动作 |
| **省一个角色** | 21 天工期里，一个只做单件事的角色要吃联系人位、头像、叙事、随机事件联动。砍掉它是省，不是损失 |

**连带影响**：

- `CompanyData.hint` 的语义从「经纪人线索，每周漏一条」改为「**公司偏好线索**，展示在招聘页上」
- GDD 随机事件里的「**经纪人推荐烂片**」改名「**熟人推荐烂片**」（事件本身保留）
- 「经纪人礼物」早在 Day 0 就随好感系统一起砍了
- `EventBus.hint_received` 信号保留（Boss直聘 展示线索时可以发），但**不再有「每周滴灌」这套节奏** ——
  M1 明细里的「经纪人线索邮件」这一项随之取消，M1 就此收尾

### 1.11 周循环的落地口径（Day 2）

数值表和文档都没写到那么细的地方，做周循环时撞上了几处。以下是我拍的结论 ——
**前 6 条是确定的口径，后 3 条属内容判断，已登记为待办请狗牙确认**。

| # | 口径 | 结论 |
|---|---|---|
| 1 | **什么进 `.tres`，什么留在常量里** | 可调数值（房租 / 分期 / 播出增量 / 次数上限 / 取值范围）进 `data/balance.tres`；**骨架常量**（3 周 × 7 天 × 1 点 = 21、每周投递上限 4）留 `GameState`。界线是「改动会不会牵动判定与界面」 |
| 2 | **结算顺序** | 先拿片酬 → 扣房租 → 分期 → 出报纸 → 判结局。顺序错了会出「明明赚了钱却交不起房租」。周报上的账也按这个顺序排 |
| 3 | **欠债从哪来** | **只有房租**能扣成负数。分期逾期是「这笔没交出去」，同时扣钱又记逾期等于一罚两遍 |
| 4 | **结局什么时候判** | **只在第 21 天**。中途不提前结束 —— 「被解雇」是第 21 天的状态判定，不是中途事件；中途结束会让「21 天」这个骨架白立，也剥夺玩家补救欠债的机会 |
| 5 | **片酬与演技的发放时点** | **投递那一刻就写进履历**，结算只负责发出去。中途调平衡不会让旧存档的账目前后不一致（与定角抽签同一个道理） |
| 6 | **报纸称呼的时点** | 同一期报纸上的称呼**统一**用结算后的最终知名度决定，不会前半版写「主角」、后半版写玩家名 |
| 7 | **知名度的两个来源** | 结果档 + 戏份档**相加**（主角 + 高分 = 3+2 = 5）。数值表原先只写了其中一半，已在 `balance.tres` 与注释里补齐 |
| 8 | **「好剧 / 烂剧」怎么定** ⚠️ 待确认 | 按**公司档次**：A 烂片厂 / B 草台班子 = 烂剧，C/D/E = 好剧。依据是 `news/README.md` 的「作品质量（公司档次）决定标题的背景」。⚠️ 但同文档还有一句「好剧或烂剧仍应按本次项目的结果判定」——**若按匹配度判，「好剧 × 低分」这一格永远取不到，二维表会塌成一维**。见待办 17 |
| 9 | **逾期的分期能不能补交** ⚠️ 待确认 | **不补**。付不出就永久缺一期，只扣风评 −5。代价是**缺一期就凑不齐 PS5 费 → 拿不到影后**。数值表只写了惩罚，没写能不能补。见待办 18 |
| 10 | **公司演技门槛只能在「周与周之间」跨越** ⛔ 已经造成一个死局 | 演技的增量在**周末结算**时才兑现（决策 1.5），所以每一周**之内**演技是冻结的。推论：**一次投递能碰到的门槛上限 = 上一周结束时手上的演技 + 本周表演课那 3 点**。算得再满也只到 **21**（7 → 18 → 21），而 E 门槛写的是 25 —— 于是「影后」不可达（模拟器实测确认）。**以后定公司门槛，必须先算这个上限。** 见待办 24 |

> **另一条不算口径、但值得写下来**：**打工与上课是即时到账**，只有**投递出去的作品**
> 才等到周末 —— 决策 1.5 的「全部留到周末」说的是播出收入，不是所有收入。
> 三者混在一起，「今天打完工还交得起明天的学费吗」就没法回答。

### 2.2 数据驱动

部件、公司、条件、事件、邮件、新闻全部走 `.tres` Resource。
**策划改数值不改代码**——21 天工期里这点能救命，也是狗牙能独立推进文案的前提。

### 2.3 数值模拟器（提前到 Day 13）

`tools/balance_sim.gd` 用 `--headless` 跑，不依赖任何场景。

必须写**两种 agent**，它们测的是完全不同的东西：

| Agent | 测什么 |
|---|---|
| **随机 agent** | 收益分布、破产率、结局分布 |
| **贪心 agent** | **极端路线的可达性**——按"门槛刚好够 + 单位收益最高"做局部最优，验证「影后」和「龙套之王」两条路真的走得通 |

> 随机 agent **无法**证明可达性：随机乱投几乎必然摸不到演技 ≥ 25。
> 这一点必须在 Day 13 就跑起来，不能拖到 Day 19——那时发现数值不通已经来不及改了。
