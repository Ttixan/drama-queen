### 关于「部件集冻结」—— 这条阻塞是我自己造出来的，已撤销

原本写着「Day 2 冻结 32 张部件集」，把**体验目标**错当成了**技术依赖**：

| 我以为的依赖 | 实际 |
|---|---|
| 判定引擎需要 32 张图 | ❌ 引擎吃的是**情绪向量**，喜/怒/哀三个方向能拼出来就够跑 |
| 录像机需要美术就位 | ❌ `.tres` 定义情绪向量，**PNG 只是皮肤**，占位色块照样跑通全链路 |
| 美术交图前程序得等着 | ❌ 反过来 —— **我把 32 件定义和图片规格定死，扉师按规格交图** |

要冻的不是**数量**，是**规格**，而那是程序的活，已经做完了：

```
尺寸  512×512 PNG，透明背景
锚点  所有部件共用同一张画布，人脸中心 = 画布中心（直接叠加即对齐，不需要偏移表）
命名  assets/parts/{slot}_{tier:02d}.png
情绪  定义在 data/parts/*.tres 里，美术不用管
```

**唯一真正卡玩法的美术约束是梯度**：每个槽位得同时有「正效价 / 中性 / 负效价」三档部件。
缺了负效价件，玩家拼不出递减曲线和帧间反转，**D 和 E 两关会直接变成死关**。
这条已经写成自动校验（`tools/test_data.gd` 的 `_check_gradient`），扉师交图后跑一次就知道够不够。
